# RGB21 → ミニDIN8 変換基板

市販のミニDIN8ケーブルを半分に切り、切った側に **RGB21(JP21)のメスコネクタ**を
付けて、ゲーム機の RGB21 ケーブルを RetroCastX の第2映像入力(J13、FRAMEMEISTER 互換の
ミニDIN8)に挿せるようにする。この基板は RGB21 コネクタのシェル(カバー)の中に収める
三角形の中継基板。

```
ゲーム機 ── RGB21ケーブル(オス) ─┐
                                  ▼
             ┌─ RGB21 メス(J1) ── 基板の端を2列の半田端子で挟む
  シェルの中 │        │ 素通し(部品なし)
             ├─ 芯線パッド(J2) ─ 表4個・裏4個 ─┬ ミニDIN8ケーブル ── RetroCastX J13
             └─ シールドのパッド(J3) ─────────┘
                  └ タイラップ用スロット(H1)でケーブルを基板に縛る
```

回路は**素通しの配線だけ**。分圧・終端・同期分離は入れない。FRAMEMEISTER 付属の
「ミニDIN8→RGB21」ケーブルも素通しで(2026-09-21 に分解して確認)、レベル合わせは
RetroCastX 側(75Ω終端・CSYNC の 1/2 分圧)でやる。

## 結線

| 信号 | RGB21(J1) | ミニDIN8(J2) | J2 の面 |
|---|---|---|---|
| R | 15 | 8 | 裏 |
| G | 19 | 7 | 裏 |
| B | 20 | 6 | 裏 |
| 同期(CSYNC) | 9(コンポジット入力) | 3 | 表 |
| 音声 L | 1 | 2 | 表 |
| 音声 R | 5 | 1 | 表 |
| GND | 3, 4, 7, 8, 13, 14, 17, 18 | 4 | 表 |
| シェル(FG) | 21 | シールド(編組) | J3(スルーホール) |
| 使わない | 2, 6, 10(モニタの出力), 11 AV制御, 12 Ym, 16 Ys | 5(パッドはあるがどこにも繋がない) | 裏 |

- RGB21 のピン名はモニタ(受け側)から見た名前。ゲーム機のケーブルを挿すので、
  ゲーム機の出力は「入力」のピンに来る。出典: ja.wikipedia「RGB21ピン」と
  retrogamingcables の JP21 表(R/G/B/同期/音声で一致)。
- 同期は 9番。RGB21 には同期専用ピンが無く、ゲーム機は CSYNC かコンポジット映像を
  ここに出す。
- ミニDIN8 は FRAMEMEISTER RGB IN と同じ並び(`hardware/adc-frontend` の
  `MiniDin8Rgb` の docstring)。5番は使わないが、芯線の端を留めるためのパッド(どこにも繋がない)がある。
- FG(シェル/シールド)は GND と分けてある。RetroCastX 側で J13 のシェルが GND に
  繋がるので、ケーブルを挿せば同電位になる。
- **J2 はピン番号順に並べてある**: 表が 1 2 3 4(表から見て左→右)、裏が 5 6 7 8 で、
  1 の真裏が 5、2 の真裏が 6 … になる。この基板の目的は芯線を付けやすくすることなので、
  基板上の配線が交差しても番号順を優先した。シルクにはパッドの脇にピン番号、その外に
  信号名を書いてある。表・裏は J2 のフットプリントから見た面で、PCB 上で J2 を裏返して
  置けば入れ替わる。
- **シールド(FG)は J3 に分けた**: より合わせた編組は太く、芯線のパッドと並べると
  隣に触れやすいので、離して置ける別部品のスルーホールパッド(直径 3.5mm・穴 1.8mm)にした。
  表裏どちらからでも付けられ、穴に通せば抜けにくい。
- **芯線の色はケーブルごとに違う。** 半田付けの前に、プラグのピンと芯線の導通を
  テスタで確かめて色を控えること。

## 回路は kinema で書いている

atopile ではなく [kinema](https://github.com/toyoshim-i/kinema) を試している。
Verilog の構造記述のサブセットで部品と接続を書き、KiCad のネットリストを生成する。
**回路図(.kicad_sch)は無い。** 正本は `src/` と `lib/` の `.v`。

| ファイル | 中身 |
|---|---|
| `src/rgb21_breakout.v` | 回路(J1 と J2・J3 の接続) |
| `lib/parts.v` | 部品(ピン番号と電気的な向き) |
| `rgb21_breakout.pretty/` | 自作フットプリント。**`tools/gen_footprints.py` の生成物なので手で直さない** |
| `fp-lib-table` | 上のフットプリントを `rgb21_breakout:` で参照する表 |
| `kinema.toml` | kinema の設定 |
| `rgb21_breakout.kicad_pcb` | 基板。配置・配線はここで手作業 |
| `tools/make_board.py` | PCB を最初の1回だけ作ったスクリプト(PCB があれば何もしない) |

### kinema の入れ方

2026-11-23 時点で GitHub Releases の最新バイナリ(v0.5.0)はソースの版(0.6.4)より
古いので、ソースから入れた(Rust が要る):

```sh
git clone https://github.com/toyoshim-i/kinema
cargo install --path kinema/crates/kinema-cli
```

### 回路を変えたとき

このフォルダで:

```sh
kinema fmt src/*.v lib/*.v           # 正規形に整形(check の fmt 段が要求する)
kinema check --stage lint            # 文法・接続・フットプリントの有無・パッド数
kinema netlist -o build/rgb21_breakout.net
```

そのあと PCB エディタで **File → Import → Netlist…** から `build/rgb21_breakout.net`
を読み込む(**「タイムスタンプで照合」**を選ぶ)。部品の同一性は `.v` の
`(* id = "..." *)` から作られる UUID で決まるので、参照番号を変えても配置は残る。
`id` を変えると別部品扱いになり、配置が消えるので変えないこと。

配線を終えたら照合:

```sh
kinema check --stage equiv           # PCB のパッドとネットが回路と一致するか
```

R と G を入れ替えた PCB で `net-partition-mismatch` が出ることを確かめてある。

### kinema 0.6.4 で踏んだこと

- **`fp-lib-table` を相対パスで指定すると自作フットプリントが見つからない。**
  表の置き場所を `${KIPRJMOD}` にするとき親ディレクトリが空文字になり、
  `/rgb21_breakout.pretty` を探しに行って `footprint-missing` になる。自動検出でも
  同じ。`kinema.toml` で `fp_lib_table = "./fp-lib-table"` と `./` 付きで書いて回避した。
- 全ピンを `passive` にすると全ネットに `undriven-net` の警告が出る。J1 の使う信号は
  `output`、J2 の信号は `input`、J2 の GND/シールドは `power_out` にしてある。
- **`check --stage equiv` は、どこにも繋がないパッドが PCB に無くても通る。** ネットのある
  パッドしか比べないため。J2 に5番(NC)のパッドを足したとき、古いフットプリントのままの
  PCB でも照合が通った。パッドの数は `--stage lint` がライブラリ側でしか見ないので、
  フットプリントを変えたら PCB 側の更新は目で確かめる。
- タイラップのスロット(H1)は回路に無い部品なので、フットプリントに
  `(attr board_only)` を付けて照合から外している。

## 残りの作業

1. **寸法を実測して `tools/gen_footprints.py` の ★ の値を直す**:
   - ~~RGB21 端子のピッチ~~ → SCART の仕様で同じ列 3.81mm(列どうしは半ピッチ 1.905mm ずれて
     交互に並ぶ)に決めた。全幅はピン1〜21の中心で 38.1mm
   - 端子の板幅と基板に乗る長さ(パッド 2.0 × 4.0mm で仮置き)
   - 2列の間隔が基板の厚み(1.6mm)で挟めるか。合わなければ板厚を変える(1.2 / 2.0mm など)
   - どちらの列が奇数ピン(1〜19 と 21=シェル)か。今は奇数を裏、偶数を表にしてある
   - タイラップの幅・厚みとケーブルの外径(スロット 1.3 × 3.2mm、中心間 9mm)
   - より合わせたシールドの太さ(J3 の穴 1.8mm、パッド 3.5mm)

   直したら `python3 tools/gen_footprints.py` を実行し、PCB エディタで
   Tools → Update Footprints from Library。
2. **外形と配線は一通り済んだ**(2026-11-24、DRC 違反 0・未配線 0、`kinema check --stage equiv` 通過)。
   ただし上の ★ の寸法は仮置きのままなので、実測で値が変わったら外形・配置・配線を見直す。
   外形はシェル内の三角形に合わせ、J1 の原点(Fab 層の破線 "board edge")が差し込む辺。
