# RetroCastX ADC フロントエンド(TVP7002 ブレークアウト)

レトロPCのアナログRGB(VGA HD-15経由)を TI TVP7002 でデジタル化し、
24bitパラレル + DATACLK/HSOUT/VSOUT/SOGOUT を Colorlight i5 EXTボードへ渡す
**HAT基板**(EXTのP1/P2/P4に直接スタック)。GbE MagJack・**音声入力3系統**・
ArgusX制御コネクタ搭載。回路は `main.ato`(Atopile)。

## 音声入力(3系統)

| 系統 | 経路 | 変換 |
|---|---|---|
| RGB端子音声 | J10(D-SUB15)**ピン10=L / ピン11=R** → U1 PCM1808(直結) | 16bit/48kHz I2S |
| LINE入力 | J12(3.5mmステレオ) → U12 PCM1808 | 16bit/48kHz I2S |
| 光デジタル | J13(TOSLINKモジュール) → FPGA直結 | S/PDIFをゲートウェアでデコード |

- **クロック**: X2(12.288MHz XO =256fs@48kHz)→ 両ADCのSCKIとFPGA(F1=PCLKC6_1)。
  BCK/LRCKはFPGAがMCLKから分周して共通供給。**DOUTのみ個別**なので
  アナログ2系統は同時キャプチャ可能。S/PDIFのDIRチップは不要(FPGAでデコード)
- **D-SUB音声の切り離しジャンパは削除した**(2026-08-11)。当初は「VGA HD-15の
  ピン4/11はID/DDCなので、一般VGAケーブルを挿す運用では切り離せるように」という
  理由で入れていたが、**コネクタを2列DA-15(X68000式)に変えた時点で3列のVGAケーブルは
  物理的に挿せなくなり**、この理由は消えていた。その後「LINE入力優先時」と読み替えられて
  いたが、**LINE入力はADCが別(U1=D-SUB / U2=LINE)でDOUTも個別**なので D-SUB 側を切る
  必要はない。よって直結にした
- どの系統を転送するかはアプリからCONFIGパケットで選択(複数同時も可)。
  詳細は `docs/protocol-v0.md` の AUDIO / CONFIG 参照

## デジタルRGB入力(TTL RGBI + HS/VS)

アナログRGB(TVP7002経由)とは**別経路**で、PC-6001mkII/SR・PC-8801・X1 等の
**デジタルRGB**を取り込む。TTLの R/G/B/I(輝度)4bit + HS + VS の6本。

```
J13(1.25mm 8極) → ESD → 10kプルダウン → SN74LVC2G17 ×3 → FPGA(SO-DIMM P4クラスタ)
                                        (5Vトレラント・シュミット)
```

- **TVP7002は通さない**。デジタル値をADCに入れる意味は無く、TVPのH-PLLはアナログ用の
  ループフィルタ定数で固定されている。ドットクロックは**FPGA内で50〜100MHz程度の
  オーバーサンプリングから再生**する(または生サンプルのまま送ってPC側でデコードする)。
  よってクロック線は基板上に無い
- **レベル変換は必須**: レトロ機のデジタルRGBは5V TTLだが **ECP5のI/Oは5Vトレラントでは
  ない**。3.3V以上を直接入れると入力保護ダイオードが導通してFPGAを壊す。
  既存の同期バッファと**同じ SN74LVC2G17**(入力5.5Vまで許容・シュミット・出力3.3V CMOS)を
  dual×3個=6chで使う → **BOM行が増えない**
- **10kΩプルダウン**: ケーブル未接続時に入力が浮くとシュミットでも中間電位で発振する。
  各入力をGNDに落として「未接続=L」に確定。TTL出力(LOWシンク数mA)に対して10kは軽い。
  ※オープンコレクタ出力の機種を繋ぐ場合は、この抵抗を外して同じパッドに3.3Vへの
    プルアップを実装する
- **RCフィルタは入れない**。アナログ側と違い折り返しの問題が無く、逆にエッジが鈍って
  オーバーサンプリングでのドットクロック再生精度が落ちる
- **csync(複合同期)の機種**もHSピンに入れればゲートウェアで分離できる(4bit色は不変)
- アナログRGB経路とは**FPGAピンが別**なので、アナログ機とデジタル機を**両方繋いだままに
  してよい**(音声だけは排他 → デジタル機の音声は J6 の3.5mm LINE入力を使う)

### コネクタ(J13)と信号順

**YIYUAN YTC-A1251-08ABW**(1.25mmピッチ 単列8極、右アングルSMD、LCSC: C7436577)。

| pin | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | tab(9,10) |
|---|---|---|---|---|---|---|---|---|---|
| 信号 | GND | R | G | B | I | HS | VS | GND | GND |

**信号は R/G/B/I → HS/VS の自然な並び**にしている(2026-08-11 変更)。以前は
「フレーム全体を壊すのは同期なので HS/VS を GND の隣に置く」という理由で
`GND/HS/R/G/B/I/VS/GND` にしていたが、変換ケーブルを自作する前提では**並びの
分かりやすさ(取り違え防止)の方が実利が大きい**と判断して並べ替えた。
8極では信号6本+GND2本しか取れないのでGNDは両端のみで、この順だと VS(7) は GND(8) に
隣接するが HS(6) は GND に隣接しない。ケーブルが長くノイズが出る場合は同シリーズの
**10極**(GNDを1本おき)に差し替えられる(フットプリント変更のみ)。
機種ごとの変換ケーブル(8ピンDIN等 → 1.25mm 8極)は自作する。

### SO-DIMM割当(P4クラスタの空き)

ピン昇順で **VS / HS / I / B / G / R** の並び(2026-08-11 変更。レイアウト上の交差を減らすため)。

| SO-DIMM | ボール | 信号 |
|---|---|---|
| 132 | F3 (PCLKC7_1) | drgb_vs |
| 136 | H3 | drgb_hs |
| 140 | H5 | drgb_i |
| 142 | J4 | drgb_b |
| 144 | J5 | drgb_g |
| 146 | K3 | drgb_r |

★以前は「HS をクロック対応ボール F3 に置いて将来 PLL 基準に使う余地を残す」として
いたが、この並べ替えで VS が F3 に来る。実用上の損失は小さい: **ECP5 の PLL は入力
下限が数MHz級**で、15〜31kHz の HS を直接 PLL のリファレンスにはできない。ドットクロック
再生は結局デジタル(オーバーサンプリング + 分周/DDS)で行うので、クロック網に載る利点は
ほとんど無い。必要になったら **G3(pin134, PCLKT7_1) / H4(pin138, GR_PCLK7_1) が未接続の
予備**として残っているのでそちらへ移せる
(外部ドットクロックを入れたくなったら、4個目のLVC2G17を足してここへ)。

## 将来拡張用デバッグ端子(J4, 2×15)

SO-DIMM **偶数側 pin54〜94**(pin56=GNDのみ除く)= 完全に連続した空きGPIO **20本**を
2×15ヘッダへ引き出す。ソケット上でも0.6mmピッチで一列に並ぶので、
SO-DIMM昇順 ↔ ヘッダ昇順の単調割当で**交差無し**に引ける。

| ヘッダpin | 1,2 | 3-10 | 11,12 | 13-20 | 21,22 | 23-26 | 27,28,29 | 30 |
|---|---|---|---|---|---|---|---|---|
| | GND | dbg1-8 | GND | dbg9-16 | GND | dbg17-20 | GND | 3V3 |

- **3V3は角(pin30、両隣はGND)**に置き、GPIOへの誤ショートを避ける
- ネット名 `dbg01_m1` … `dbg20_f18`(番号=SO-DIMM順、末尾=FPGAボール名)
- **dbg14 = J18 = GR_PCLK2_0(クロック対応)** → 外部クロック入力に使える
- **直列保護抵抗は入れていない**。外部回路を繋ぐ実験で保険が欲しければ各線に33〜100Ωを

## ArgusX(RGBセレクタ、別プロジェクト)連携

J11(1×4: 3V3/SDA/SCL/GND)にTVP7002と共有のI2Cバスを引き出し。アプリからの
CONFIGパケット(target=ArgusX)をゲートウェアがI2C書き込みに中継し、セレクタの
入力切替をアプリから行える。ArgusXのI2Cアドレス/レジスタマップは同プロジェクト側で
確定後に反映。**I2Cアドレスの割当: TVP7002=0x5C(7bit)、MAC EEPROM=0x50/0x51
→ ArgusXは0x50-0x53と0x5Cを避けること**。

## MACアドレス(EUI-48 EEPROM)

U13/U14(24AA025E48)に工場書込みのグローバル一意MACを搭載。
ゲートウェアが起動時にI2Cで読み出してEthernetに設定する
(EEPROM未実装/読出し失敗時はローカル管理アドレス02:52:43:58:xx:xxへフォールバック)。
複数台運用・2ポートストライピング(ETH1追加時)でMAC衝突管理が不要になる。
EEPROMの空き領域(~250B)は個体設定(IP・ボード名等)の保存に使用
(旧計画のSPIフラッシュ設定ページを置き換え)。

## 回路の構成(根拠: TVP7002データシート SLES206C / OSSC rev1.8 実機回路)

- **アナログ入力**: VGA各色 → ESDアレイ → 75Ω終端 → 100nF ACカップリング → RIN_3/GIN_3/BIN_3。
  緑は追加で 1nF → SOGIN_3(Sync-on-Green対応)
- **同期入力**: HS/VS → ESD → SN74LVC2G17(シュミット、5Vトレラント)→ HSYNC_A/VSYNC_A。
  VSYNC側は 220Ω+1nF のRC遅延(データシート推奨: VSYNCエッジとHSYNCの完全一致を回避)。
  複合同期(csync)はHSYNCピンに入れれば内部セパレータが分離する(4線モード)
- **H-PLLループフィルタ**(唯一の必須外付け): FILT1→1.5kΩ+100nF→PLL_F、FILT2→4.7nF→PLL_F
- **27MHz発振器** → EXT_CLK(モード検出の安定化用。動作自体は同期駆動で可)
- **電源**: **本基板が電源マスター(既定)**。J10 USB-C(CCにRd 5.1kΩ実装 → PD充電器+
  C-Cケーブルで5V/3A受電可)から給電し、SJ1(閉=既定)でP1/P2/P4の5Vピン経由で
  **EXTボードへ逆給電**する。この運用ではEXTのスライドスイッチS1をOFFにし、EXTのUSB-Cは
  JTAG/UARTデータ専用とする。代替入力: J7 DCジャック(J10と排他)。合計消費 ≈1.2A。
  ※EXTボードのUSB-CはCC未接続(Rdなし)のためC-Cケーブルでは受電できない(回路図で確認済み)。
  5Vレールから →
  - AZ1117H-3.3 → 3.3V IO系(IOVDD、発振器、バッファ、プルアップ)
  - AZ1117H-3.3(別個)→ 3.3Vアナログ(A33VDD)
  - AZ1117H-ADJ + 120Ω/62Ω分圧 ≈1.896V → AVDD・PLL_AVDD(各フェライトビーズ経由)
  - TLV70019(1.9V)→ DVDD
- **未使用入力**: video系は10nF、SOG系は1nFでGNDへ(データシート指定)
- **ストラップ**: PWDN/TMS/CLAMP/COAST/HSYNC_B/VSYNC_B→GND、I2CA→GND(I2Cアドレス0xB8)、
  RESETB は2.2kプルダウン(FPGAがHighで解除)、SDA/SCL 2.2kプルアップ

## Ethernet LED: PHY直結 / GPIO の二経路(2026-08-11)

MagJackのリンク/アクティビティLEDを **2経路**用意し、実装で選べるようにした。

```
経路A(既定) i5モジュール底面のPHY LEDパッド → ポゴピン(PG5-8) → 220Ω → MagJack pin11/14
経路B(代替) FPGA GPIO → はんだジャンパ(JP4-7, 既定=開) → 220Ω → 同じアノード
```

**きっかけ**: [chenzhuoyu/rainbow-board](https://github.com/chenzhuoyu/rainbow-board) が
JTAGと同じ流儀で、**PHYのLED出力をモジュール底面からバネ端子で拾って**MagJackのLEDへ
入れていた。同じ HR911130A 系MagJackで、LEDピンの割当(11/14=アノード, 12/13=カソード)も
本設計と一致していた。

- **経路Aの利点**: ゲートウェア不要(PHYが出す本物のリンク/アクティビティ)。
  **ビットストリームを焼く前から光る**ので「そもそもリンクしているか」が即分かる。
  FPGAのGPIO 4本(io_r1/io_t1/io_u1/io_y2)も解放される
- **経路Bへの逃げ道**: ポゴピンの接触不良やPHYパッド位置の食い違いに備え、GPIO側を
  直列はんだジャンパにしてある。**基板改造なしで切り替えられる**
- ★**同時に両方生かさないこと**。両方だとPHY出力とGPIO出力が440Ω越しに押し合う
  (≒7.5mA。壊れはしないが表示が濁る)。経路A運用時はゲートウェアでGPIOを入力にしておく
- 抵抗は **220Ω**(既存部品と同一 = BOM行が増えない)。3.3V・Vf≒2Vで約6mA。
  rainbow-boardは68Ω(≒19mA)だが、i5モジュール側に直列抵抗が入っている可能性があり
  (モジュール自身のLEDと並列にタップしている疑い)、PHYのLEDピンへ流し過ぎるリスクを
  避けて安全側にした。暗ければ100Ω→68Ωへ下げる

### ポゴピン位置(rainbow-boardの実測値)

SO-DIMMソケット原点からの相対位置。**JTAGの縦33mmが本設計の想定値と一致した**ので、
この座標系は信用できる。

| 端子 | 相対位置 | 本設計 |
|---|---|---|
| JTAG 1×04 | (−24.15, −33.30) | PG1-4(TCK/TMS/TDI/TDO) |
| ETH1 LEDs 1×02 | (−22.08, −29.59) | PG5(D2=緑) / PG6(D4=黄) |
| ETH2 LEDs 1×02 | (−22.15, −15.43) | PG7(D2=緑) / PG8(D4=黄) |

※rainbowのソケット向き基準。本設計はソケットの回転が違うので、レイアウト時に
「ソケット原点から見た同じ相対位置」へ置き換えること。rainbowのLED用ドリルは
**0.5mm**(JTAGの0.9mmより細い)。

### ネット名

`eth{1,2}_phy_led_d{2,4}`(PHYタップ) / `eth{1,2}_led_{g,y}_gpio`(GPIO) /
`eth{1,2}_led_{g,y}_gpio_sj`(ジャンパ〜抵抗) / `eth{1,2}_led_{g,y}_anode`(合流点)

## Colorlight i5 EXTボードとの接続(2026-07-25 調査確定)

- **EXTボードにRJ45は無い**。i5モジュール上のGbE PHY×2の差動ペア(MDI)はヘッダ**P1**
  (2×15)に出ているだけ。→ **本基板にMagJack(J8+J9)を搭載済み**。回路は
  [kazkojima氏 i5ether](https://github.com/kazkojima/colorlight-i5-tips)準拠
  (1000BASE-T netboot/nfsroot動作実績あり):MDIはDC結合のまま、PHY側CTは各0.1µF→GND
  (B50612Dは内部バイアスで無給電可)、Bob-SmithはMagJack内蔵、GND-シャーシ間4.7nF/2kV×2。
  **ETH2側ペア=LiteXのphy0** を使用(PHY番号とコネクタ名の対応は逆転に注意)
- EXTボードのGPIOヘッダは P2–P6(各2×15メス、GPIOは1ヘッダあたり18〜20本)。USB-C は
  DAPLink(JTAG書き込み+UARTコンソール)+VBUS。HDMIは出力のみ。SDスロット無し
- **EXTのUSB-C電源には要注意(回路図 schematic/i5-i9-extboard.pdf で確認)**: PDコントローラなし・
  **CC端子未接続(Rd 5.1kΩなし)**のため、規格準拠のC-Cケーブルでは受電不可(A→Cケーブル専用)。
  VBUS→ヒューズF1(定格不明)→スライドスイッチS1→5Vレール直結。
  → 本基板をJ10から給電しS1をOFFにする「逆給電」運用でこの問題を回避する
- **ECP5のクロック対応(PCLK)ボールが出ているヘッダ**(prjtrellis DB照合結果):
  - P2: J20(PCLKT2_0), K20(PCLKC2_0), L20(PCLKT3_1), L18(GR_PCLK3_1)
  - P3: E2(PCLKC7_0)
  - **P4: F2(PCLKT7_0), F1(PCLKC6_1), F3(PCLKC7_1), G3(PCLKT7_1), H4(GR_PCLK7_1)** ← 最多
  - P6: J18(GR_PCLK2_0)
- **HAT形式(スタック)を正式採用**: 本基板は裏面の2×15ピン(J2/J4/J8)でEXTボードの
  P2/P4/P1メスヘッダに直接嵌合する。ピン配置は1対1ミラーのため、寸法不一致時は
  2×15リボンケーブルでフォールバック可。**製作前にEXTボード実寸(ヘッダ間距離・
  i5モジュールの高さ・ソケット嵌合高さ≈11mm)の採寸が必須**
- 信号は P2/P4 の2ヘッダに集約(EXT側1ヘッダのGPIOは18〜20本でRGB24bitは1本に収まらない):
  - **J2 = P2ミラー**: R9-R2→J20,G20,L18,K20,M18,L20,N17,N18 / G9-G2→U17,P18,T17,U18,P17,M17,R18,R17 / B9-B6→C18,T18,U16,K18
  - **J4 = P4ミラー**: DATACLK→**F2(PCLKT7_0)**、B5-B2→E1,E4,H3,H5、HSOUT→J5、VSOUT→A2、
    SOGOUT→K4、FIDOUT→B2、SDA→K3、SCL→K5、RESETB→B3、
    音声: MCLK→**F1(PCLKC6_1)**、BCK→G3、LRCK→H4、DOUT(DSUB音声)→F3、
    DOUT(LINE)→J4、S/PDIF→E19(空きなし)


## RGB入力のアンチエイリアスフィルタ(必須)

TVP7002のアナログ入力に **220Ω直列 + 33pF並列** のローパスを入れている。
これは省略できない。試作機で後付けして効果を実測した。

### なぜ必要か

TVP7002のアナログ帯域は **350〜500MHz**(データシート実測値)ある一方、こちらの
サンプリングは **8〜44MHz** しかない。ナイキスト周波数(4〜22MHz)より上の雑音は
すべて折り返して絵に畳み込まれる。TVP内蔵の帯域制御(レジスタ 3Fh)は

    0h = Highest video bandwidth (default)
    Fh = Lowest video bandwidth (~95 MHz)

で最小でも50MHz以上あり、この用途には使えない。**外付けが必須**。

### 実測(X68000 31kHz 256x256、pll_divide=1104 / 34.775MHz)

試作機に 220Ω + 15pF(TVPの入力容量10pFと合わせて実効25pF、遮断28.9MHz)を
後付けした前後:

| | フィルタ前 | フィルタ後 |
|---|---|---|
| ノイズ(暗部の時間ゆらぎ) | 40〜60% | **3.9%** |
| 暗部の底(明線直後の残留) | 9.2 | **0.01** |
| エッジ後のリンギング | 19サンプル周期で6山(+3〜15) | **消滅** |

「暗いはずの所が暗くない」「エッジの右に減衰しながら繰り返す像が出る」という
2つの症状は、どちらも折り返しが原因だった。エッジそのものの立ち上がりは
2サンプル(58ns)で完了しており、フィルタによる鮮鋭度の低下は見られない。

なおリンギングは、サンプルクロックを変えても**サンプル数で一定(約19)**だった。
アナログの共振なら時間で一定になるはずで、この違いが折り返しだと見抜く決め手に
なった。ケーブル長(2m=往復20ns)では546nsの周期は説明できない点も一致する。

### 定数の選び方

TVPの入力容量10pF(データシート CI)が並列に入る。

| C(外付け) | 実効 | 遮断周波数 | 備考 |
|---|---|---|---|
| 15pF | 25pF | 28.9MHz | 試作で実測した値 |
| **33pF** | **43pF** | **16.8MHz** | 採用値 |
| 47pF | 57pF | 12.7MHz | さらに折り返しを削るが最細部が鈍る |

採用値の16.8MHzは、最も高いモード(31kHz 768ドット、ドットクロック34.78MHz)の
ナイキスト17.4MHzにほぼ一致する。隣接ドットが交互に変わる最細パターンは3dB
落ちるが、それはそもそも折り返す成分なので抑えるのが正しい。鮮鋭さを優先するなら
15〜22pFに下げる。

**c_aa は TVP の入力ピン直近に置くこと。** r_aa は結合コンデンサの直後で構わない。
R/G/B の3チャンネルとも同じ値にする(片方だけ違うと色ずれになる)。

### 補足: ビーズは使わないこと

映像信号にフェライトビーズを入れると、低周波ではインダクタとして振る舞うため
コンデンサとLC共振を作り、まさにここで消したリンギングを自分で作り込むことに
なる。ビーズは電源ライン専用。

### 未使用アナログ入力(基板設計では対応済み)

データシートは未使用のアナログ入力を10nFで、未使用SOG入力を1nFでGNDへ落とすよう
指定している。**main.ato では対応済み**(nc_caps × 7、nc_sog_caps × 2)。手半田の
試作機に無いだけなので、基板を起こせば解消する。

## TVP7002のレジスタ設定(実測で決めたもの)

初期化で書いている値のうち、**実測で効果を確認して決めた**ものを記録する。
どれも既定値のままでは症状が出る。

### 3Fh = 0Fh (アナログ映像帯域を最小に)

外付けRC(28.9MHz)を入れてもエッジの直後に残っていた**1つ目のエコー**が消える。

| 3Fh | 残留エコー(明線直後の超過) |
|---|---|
| 00h(最大帯域・既定) | +2.55 |
| 08h | +1.82 |
| 0Ch | +1.01 |
| **0Fh(最小≈95MHz)** | **+0.01** |

単調に減り、戻すと再現する。外付けが28.9MHzで切っているので効かないと予想したが
実際には完全に消えた。残留エコーの成分が95MHz以上にあり、単極RCでは95MHzを10dB
しか落とせなかったためと考えられる。

代償はエッジの立ち上がり(2サンプル=58ns)が変わらないまま、最細部の振幅が6%
落ちるだけ。

### 2Ah = 87h (ファインクランプのCMオフセットを有効に)

白ベタ領域の**先頭20サンプル(約576ns)だけ2〜3%暗くなる**症状が、GとBにだけ
出ていた(Rには出ない)。データシートで 2Ah は `Fine GB`(G/B共通)と `Fine R`
が別ビットになっており、症状の出方と一致した。

| 2Ah | R | G | B |
|---|---|---|---|
| 07h(既定) | +0.2 | +2.6 | +2.0 |
| 0Fh/17h/1Fh(時定数を短く) | +0.2 | +2.6 | +2.0 |
| **87h(CM Offset 有効)** | +0.1 | **+2.2** | **+0.3** |

**時定数(bit[4:3])は全く効かなかった**。効いたのは CM Offset(bit7)で、
データシートの "can be enabled to improve isolation and channel crosstalk" の
とおり、原因はクランプの応答ではなく**チャンネル間のクロストーク**だった。
白レベルは 102.7% → 102.8% で副作用は見られない。

### 残件: Green の +2.2%

Blue はほぼ解消したが Green に +2.2% が残っている。

測定した試作機は手半田で、**Green だけ信号線が長い**。切り分けの結果、これが
残差の原因と考えられる。

| 検証 | 結果 |
|---|---|
| X68000側で G と B を入れ替え | **症状は G のまま移らない** → 信号源は無罪 |
| 3chの立ち上がり時間 | 1.50サンプルで完全一致 → 部品値・半田付けに差なし |
| Green の AGND を最短化 | 変化なし |
| SOGIN_3(未配線)に0.01µF追加 | 変化なし |
| クランプ時定数 (2Ah bit[4:3]) | 変化なし |

信号を入れ替えても症状が基板の Green 経路に留まることから、**基板側で拾っている**
と判断できる。部品も設定も対称なので、残る非対称は配線長だけ。

CM Offset の効き方もこれで説明できる。あれは TVP 内部の分離を改善するものなので、
チップ内で完結する分(Blue)は解消したが、**基板上で拾っている分(Green)には
効かなかった**。

**基板を起こして3本を短く等長にすれば消える見込み**なので、この数字を基板設計の
判断材料にしないこと。基板版でも残る場合は、SOGスライサの停止(2Bh bit6)を試す
価値がある(未検証)。ただし将来 SOG 入力に対応する際に必要な経路なので、無効化
するなら実行時に切り替えられる形にすること。

### 08h/09h/0Ah = 35/33/39 (細ゲイン。白をフルスケール付近へ)

既定の 00h(ゲイン1.0)だと **白が 210/255 (82%) までしか届かず**、階調とSNRを2割
損していた。粗ゲインは既定で既に1.2倍あり、データシートも "For a normal PC graphics
input, the fine gain is used mostly" としているので、細ゲインで補う。
チャンネル別なのでホワイトバランスも同時に合う(Rが2%低かった分を補正)。

実測して決めた(白の90%点と、生1フレームでの255画素数):

| NFG (B,G,R) | 白の90%点 | 飽和画素 |
|---|---|---|
| (54, 51, 58) | 251.5 | 5626 |
| (45, 42, 49) | 244.5 | 608 |
| **(35, 33, 39)** | **237** | **0** |
| (26, 23, 30) | 229 | 0 |

飽和は不可逆で、ノイズの山か信号の山かを区別できない。3%明るくするために階調を失う
のは割に合わないので、飽和ゼロの点を選んだ。黒は全チャンネル 0 のままでクランプは
正常。CONFIG key 0x1C/0x1D/0x1E で実行時にも変更できる。

**症状としては「白い文字が薄いグレーに見える」という形で出る。** 明るいゲーム画面
では気付きにくく、白文字の多い画面で目立つ。補間や帯域の問題と紛らわしいので注意。

### 効かなかった/悪化した設定(再調査を避けるための記録)

**03h(VCOレンジ+チャージポンプ)** — TVP既定 A8h は VCO Medium(70〜135MHz用)で、
こちらのピクセルクロック(8.7〜44MHz)とは規定範囲が合っていない。データシートどおり
Ultra low + ICP=3 の 18h にして実測したが、**効果が無かった**。

**05h/06h(クランプ開始/幅)** — データシート Table 13 の PC graphics 推奨は 06h/10h
だが、**ノイズが3割悪化する**。落ち込みは僅かに改善する(G +1.5 → +1.1)が割に合わない。
推奨値はクランプ窓が狭く黒レベルの平均化が減るため。X68000のバックポーチは一般的な
PCより長いので、既定の広い窓(開始50・幅32)の方が有利だった。
**データシートの推奨がそのまま最適とは限らない例。**

31kHz 256x256(pll 1104)での実測。同じ並びを電源条件を変えて2回測り、いずれも同じ
関係になった。

| 条件 | ノイズ | R | G | B |
|---|---|---|---|---|
| 既定 A8h/32h/20h | **3.33%** | +0.7 | +1.5 | +0.9 |
| 03h=18h のみ | 3.28% | +0.7 | +1.4 | +0.9 |
| 05h/06h=06h/10h のみ | **4.41%** | +0.6 | +1.1 | +0.7 |
| 両方 | 4.65% | +0.7 | +1.1 | +0.7 |
| 既定に戻す(再現確認) | 3.24% | +0.7 | +1.5 | +0.9 |

**測定時の注意**: ノイズの絶対値は電源で大きく動く(下記)ので、条件間は必ず連続して
測り、最後に基準へ戻して再現を確認すること。また設定が本当に届いたかを毎回確認する
こと(CONFIG応答を見る)。**古いファームでキーが未対応だと設定が黙って無視され、
「効果なし」に見える**。実際それで一度誤った結論を出しかけた。

### ノイズは電源に強く依存する ← PCB設計で最重要

同じ設定・同じモードで、USBの接続経路を変えただけでノイズが3倍動いた。

```
1.1%  〜  3.3%  〜  3.9%     (接続経路の違いだけ)
```

試作時はUSBハブが4〜5段に連なっており、段数や挿す位置で電源の質が変わっていた。
レジスタ設定をいくら詰めても、この振れ幅の方がはるかに大きい。**基板では電源の質を
最優先すること**(アナログ電源の分離、デカップリング、USBから引く場合の経路)。
評価するときは電源条件を固定し、変えたら基準値を取り直すこと。

### 実行時に変更できる

切り分けのため CONFIG で変えられるようにしてある(ビルドし直さずにA/Bできる)。

| key | 対象 |
|---|---|
| 0x17 | 3Fh 映像帯域 (0〜15) |
| 0x18 | 2Ah ファインクランプ (8bit) |
| 0x19 | 03h PLL(VCOレンジ+チャージポンプ) |
| 0x1A | 05h クランプ開始位置 |
| 0x1B | 06h クランプ幅 |

## ★`ato build` の後に必ず実行すること

`ato build` は **atopile がモデル化していない要素を書き出し時に落とす**。
落ちるものが2種類あり、どちらも黙って消えるので毎回機械的に戻すこと。

```sh
python3 tools/restore_tuning_patterns.py   # GbEの等長配線が基板外へ飛ぶのを防ぐ
python3 tools/restore_pcb_settings.py      # 基板の原点とリビジョン番号を戻す
```

### 1. 等長配線オブジェクト

`(generated ... (type tuning_pattern))` の中身が捨てられ、KiCad が開いたときに
パターンを作り直して **member の配線を基板外へ移動させる**。実際に2回発火し、
GbEの等長配線67本が x=277.5 まで飛んだ。詳細は `tools/restore_tuning_patterns.py`。

### 2. 基板の原点とリビジョン番号 (2026-08-19 に特定)

```
(title_block (rev "v0.9.0"))    リビジョン番号
(setup (grid_origin 87.5 149))  基板の原点(グリッド原点)
```

`title` は残るのに `rev` だけ消える。atopile の非テストコードには PCB の
title_block も grid_origin/aux_axis_origin も一切現れない(title_block は回路図側の
変換にしか出てこない)。

**実証**: 両方が入った状態で `ato build` を実行したら両方消えた。再現性あり。

**git履歴**: 消失は必ず `ato build` を伴うコミット、復活は pcbnew 作業のコミット。

```
47868cf  grid 復活   基板固定用M2.6ネジ穴を追加(pcbnew作業)
ab25097  grid 消失   配線途中のスナップショット
f916edc  grid 復活   配線途中のスナップショット
7156ba7  grid 消失   J9の3Dモデルオフセットを反映(ato build)
34391de  grid 復活   配線途中のスナップショット
715e368  grid 消失   デジグネータを宣言順に振り直す(ato build)
fa3fe14  grid+rev 復活  v0.9.0の製造データを出した時点を記録(pcbnew作業)
ac85734  grid+rev 消失  FT2232HL を CH347F に置き換える(ato build)
```

利用者は4回設定し直しており、そのたびに次の build で失われていた。
**grid_origin はガーバー/ドリルの出力原点**なので、消えたまま製造データを出すと
座標系が変わり、実装機データや過去の版と突き合わせられなくなる。

値は `tools/pcb_settings.json` に置いて git で追跡する。pcbnew で変えたら
`python3 tools/restore_pcb_settings.py --capture` で取り込み直すこと。

### 落ちないが書式が変わるもの(実害なし)

`ato build` は他にも書式を正規化する: パッドの `(layers)` の並び順、数値の桁、
`(locked no)` 等の既定値の明示、カスタムパッドの `(fill yes)`/`(anchor circle)` の削除。
J2(USB-C)のカスタムパッド4個で確認したところ、**実効形状のバウンディングボックスは
1.300x0.600mm で前後完全一致**しており、KiCad が既定値で同じ形に解決する。実害はない。

## 手半田実装用の発注リスト(DigiKey / Mouser)

`ato build` が出す `build/builds/default/default.bom.csv` は **JLCPCB 発注用**で、
LCSC 品番が主役になっている。この基板は中国国内ブランド(UNI-ROYAL の抵抗、FH の
コンデンサ、HANRUN の RJ45、YXC の水晶など)を多用しているので、そのまま DigiKey や
Mouser の BOM ツールに投げても**半分近くが「該当なし」で落ちる**。

`tools/gen_order_bom.py` が `tools/order_sourcing.json` の読み替え表を当てて、
アップロードできる形に整える。

```sh
python3 tools/gen_order_bom.py --tag v0.9.0            # 1枚分
python3 tools/gen_order_bom.py --tag v0.9.0 --boards 5 # 5枚分
```

| 出力 | 用途 |
|---|---|
| `orders/<tag>/digikey-bom.csv` | DigiKey myLists → BOM Manager にアップロード |
| `orders/<tag>/mouser-bom.csv` | Mouser BOM ツールにアップロード |
| `orders/<tag>/lcsc-bom.csv` | LCSC でしか買えない分 |
| `orders/<tag>/README.md` | 人が読む用(注意点・読み替え理由つき) |

アップロード用 CSV には**実在する製造元品番だけ**を載せている。汎用ピンヘッダや
ネジを説明文のまま混ぜると照合結果が「該当なし」だらけになって読めなくなるので、
それらは README の「どこでも買える汎用品」に分けてある。

★読み替え表に無い LCSC 品番があるとエラーで止まる。回路を変えたら
`tools/order_sourcing.json` も更新すること(黙って落とさないための仕掛け)。

### 入手性で注意が要る部品

| 部品 | 事情 |
