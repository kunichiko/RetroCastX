# RetroCastX ADC フロントエンド(TVP7002 ブレークアウト)

レトロPCのアナログRGB(VGA HD-15経由)を TI TVP7002 でデジタル化し、
24bitパラレル + DATACLK/HSOUT/VSOUT/SOGOUT を Colorlight i5 EXTボードへ渡す
**HAT基板**(EXTのP1/P2/P4に直接スタック)。GbE MagJack・**音声入力3系統**・
ArgusX制御コネクタ搭載。回路は `main.ato`(Atopile)。

## 音声入力(3系統)

| 系統 | 経路 | 変換 |
|---|---|---|
| RGB端子音声 | J1(D-SUB15)ピン4=L/11=R → SJ2/SJ3 → U11 PCM1808 | 16bit/48kHz I2S |
| LINE入力 | J12(3.5mmステレオ) → U12 PCM1808 | 16bit/48kHz I2S |
| 光デジタル | J13(TOSLINKモジュール) → FPGA直結 | S/PDIFをゲートウェアでデコード |

- **クロック**: X2(12.288MHz XO =256fs@48kHz)→ 両ADCのSCKIとFPGA(F1=PCLKC6_1)。
  BCK/LRCKはFPGAがMCLKから分周して共通供給。**DOUTのみ個別**なので
  アナログ2系統は同時キャプチャ可能。S/PDIFのDIRチップは不要(FPGAでデコード)
- **SJ2/SJ3(既定: 閉)**: D-SUB15のピン4/11はVGA規格ではID/DDC。音声結線のある
  レトロPC用ケーブルでは閉、一般VGAケーブル(DDC結線あり)を挿す運用では開ける
- どの系統を転送するかはアプリからCONFIGパケットで選択(複数同時も可)。
  詳細は `docs/protocol-v0.md` の AUDIO / CONFIG 参照

## ArgusX(RGBセレクタ、別プロジェクト)連携

J11(1×4: 3V3/SDA/SCL/GND)にTVP7002と共有のI2Cバスを引き出し。アプリからの
CONFIGパケット(target=ArgusX)をゲートウェアがI2C書き込みに中継し、セレクタの
入力切替をアプリから行える。ArgusXのI2Cアドレス/レジスタマップは同プロジェクト側で
確定後に反映。**I2Cアドレスの割当: TVP7002=0x5C(7bit)、MAC EEPROM=0x50/0x51
→ ArgusXは0x50-0x53と0x5Cを避けること**。

## MACアドレス(EUI-48 EEPROM)

U13/U14(24AA025E48)に工場書込みのグローバル一意MACを搭載。
ゲートウェアが起動時にI2Cで読み出してEthernetに設定する
(EEPROM未実装/読出し失敗時はローカル管理アドレス02:52:43:58:xx:xxへフォールバック)。
複数台運用・2ポートストライピング(ETH1追加時)でMAC衝突管理が不要になる。
EEPROMの空き領域(~250B)は個体設定(IP・ボード名等)の保存に使用
(旧計画のSPIフラッシュ設定ページを置き換え)。

## 回路の構成(根拠: TVP7002データシート SLES206C / OSSC rev1.8 実機回路)

- **アナログ入力**: VGA各色 → ESDアレイ → 75Ω終端 → 100nF ACカップリング → RIN_3/GIN_3/BIN_3。
  緑は追加で 1nF → SOGIN_3(Sync-on-Green対応)
- **同期入力**: HS/VS → ESD → SN74LVC2G17(シュミット、5Vトレラント)→ HSYNC_A/VSYNC_A。
  VSYNC側は 220Ω+1nF のRC遅延(データシート推奨: VSYNCエッジとHSYNCの完全一致を回避)。
  複合同期(csync)はHSYNCピンに入れれば内部セパレータが分離する(4線モード)
- **H-PLLループフィルタ**(唯一の必須外付け): FILT1→1.5kΩ+100nF→PLL_F、FILT2→4.7nF→PLL_F
- **27MHz発振器** → EXT_CLK(モード検出の安定化用。動作自体は同期駆動で可)
- **電源**: **本基板が電源マスター(既定)**。J10 USB-C(CCにRd 5.1kΩ実装 → PD充電器+
  C-Cケーブルで5V/3A受電可)から給電し、SJ1(閉=既定)でP1/P2/P4の5Vピン経由で
  **EXTボードへ逆給電**する。この運用ではEXTのスライドスイッチS1をOFFにし、EXTのUSB-Cは
  JTAG/UARTデータ専用とする。代替入力: J7 DCジャック(J10と排他)。合計消費 ≈1.2A。
  ※EXTボードのUSB-CはCC未接続(Rdなし)のためC-Cケーブルでは受電できない(回路図で確認済み)。
  5Vレールから →
  - AZ1117H-3.3 → 3.3V IO系(IOVDD、発振器、バッファ、プルアップ)
  - AZ1117H-3.3(別個)→ 3.3Vアナログ(A33VDD)
  - AZ1117H-ADJ + 120Ω/62Ω分圧 ≈1.896V → AVDD・PLL_AVDD(各フェライトビーズ経由)
  - TLV70019(1.9V)→ DVDD
- **未使用入力**: video系は10nF、SOG系は1nFでGNDへ(データシート指定)
- **ストラップ**: PWDN/TMS/CLAMP/COAST/HSYNC_B/VSYNC_B→GND、I2CA→GND(I2Cアドレス0xB8)、
  RESETB は2.2kプルダウン(FPGAがHighで解除)、SDA/SCL 2.2kプルアップ

4. **色深度**: 配線は各色上位8bit(R/G/B[9:2])。J4の空き6ピンは音声系で

5. **音声まわり**: PCM1808のVCC(5Vアナログ)はFB経由で分離済み。レイアウトでは
   ADC・XOをGbE/映像系から離し、D-SUB音声の引き回しは映像RGBと並走させない。
   PCM1808/TOSLINK/3.5mmジャック/12.288MHz XOのスタブはピン番号仮割り当てなので
   フットプリント取り込み時にデータシート照合(main.ato内の注意書き参照)

## Colorlight i5 EXTボードとの接続(2026-07-25 調査確定)

- **EXTボードにRJ45は無い**。i5モジュール上のGbE PHY×2の差動ペア(MDI)はヘッダ**P1**
  (2×15)に出ているだけ。→ **本基板にMagJack(J8+J9)を搭載済み**。回路は
  [kazkojima氏 i5ether](https://github.com/kazkojima/colorlight-i5-tips)準拠
  (1000BASE-T netboot/nfsroot動作実績あり):MDIはDC結合のまま、PHY側CTは各0.1µF→GND
  (B50612Dは内部バイアスで無給電可)、Bob-SmithはMagJack内蔵、GND-シャーシ間4.7nF/2kV×2。
  **ETH2側ペア=LiteXのphy0** を使用(PHY番号とコネクタ名の対応は逆転に注意)
- EXTボードのGPIOヘッダは P2–P6(各2×15メス、GPIOは1ヘッダあたり18〜20本)。USB-C は
  DAPLink(JTAG書き込み+UARTコンソール)+VBUS。HDMIは出力のみ。SDスロット無し
- **EXTのUSB-C電源には要注意(回路図 schematic/i5-i9-extboard.pdf で確認)**: PDコントローラなし・
  **CC端子未接続(Rd 5.1kΩなし)**のため、規格準拠のC-Cケーブルでは受電不可(A→Cケーブル専用)。
  VBUS→ヒューズF1(定格不明)→スライドスイッチS1→5Vレール直結。
  → 本基板をJ10から給電しS1をOFFにする「逆給電」運用でこの問題を回避する
- **ECP5のクロック対応(PCLK)ボールが出ているヘッダ**(prjtrellis DB照合結果):
  - P2: J20(PCLKT2_0), K20(PCLKC2_0), L20(PCLKT3_1), L18(GR_PCLK3_1)
  - P3: E2(PCLKC7_0)
  - **P4: F2(PCLKT7_0), F1(PCLKC6_1), F3(PCLKC7_1), G3(PCLKT7_1), H4(GR_PCLK7_1)** ← 最多
  - P6: J18(GR_PCLK2_0)
- **HAT形式(スタック)を正式採用**: 本基板は裏面の2×15ピン(J2/J4/J8)でEXTボードの
  P2/P4/P1メスヘッダに直接嵌合する。ピン配置は1対1ミラーのため、寸法不一致時は
  2×15リボンケーブルでフォールバック可。**製作前にEXTボード実寸(ヘッダ間距離・
  i5モジュールの高さ・ソケット嵌合高さ≈11mm)の採寸が必須**
- 信号は P2/P4 の2ヘッダに集約(EXT側1ヘッダのGPIOは18〜20本でRGB24bitは1本に収まらない):
  - **J2 = P2ミラー**: R9-R2→J20,G20,L18,K20,M18,L20,N17,N18 / G9-G2→U17,P18,T17,U18,P17,M17,R18,R17 / B9-B6→C18,T18,U16,K18
  - **J4 = P4ミラー**: DATACLK→**F2(PCLKT7_0)**、B5-B2→E1,E4,H3,H5、HSOUT→J5、VSOUT→A2、
    SOGOUT→K4、FIDOUT→B2、SDA→K3、SCL→K5、RESETB→B3、
    音声: MCLK→**F1(PCLKC6_1)**、BCK→G3、LRCK→H4、DOUT(DSUB音声)→F3、
    DOUT(LINE)→J4、S/PDIF→E19(空きなし)


## RGB入力のアンチエイリアスフィルタ(必須)

TVP7002のアナログ入力に **220Ω直列 + 33pF並列** のローパスを入れている。
これは省略できない。試作機で後付けして効果を実測した。

### なぜ必要か

TVP7002のアナログ帯域は **350〜500MHz**(データシート実測値)ある一方、こちらの
サンプリングは **8〜44MHz** しかない。ナイキスト周波数(4〜22MHz)より上の雑音は
すべて折り返して絵に畳み込まれる。TVP内蔵の帯域制御(レジスタ 3Fh)は

    0h = Highest video bandwidth (default)
    Fh = Lowest video bandwidth (~95 MHz)

で最小でも50MHz以上あり、この用途には使えない。**外付けが必須**。

### 実測(X68000 31kHz 256x256、pll_divide=1104 / 34.775MHz)

試作機に 220Ω + 15pF(TVPの入力容量10pFと合わせて実効25pF、遮断28.9MHz)を
後付けした前後:

| | フィルタ前 | フィルタ後 |
|---|---|---|
| ノイズ(暗部の時間ゆらぎ) | 40〜60% | **3.9%** |
| 暗部の底(明線直後の残留) | 9.2 | **0.01** |
| エッジ後のリンギング | 19サンプル周期で6山(+3〜15) | **消滅** |

「暗いはずの所が暗くない」「エッジの右に減衰しながら繰り返す像が出る」という
2つの症状は、どちらも折り返しが原因だった。エッジそのものの立ち上がりは
2サンプル(58ns)で完了しており、フィルタによる鮮鋭度の低下は見られない。

なおリンギングは、サンプルクロックを変えても**サンプル数で一定(約19)**だった。
アナログの共振なら時間で一定になるはずで、この違いが折り返しだと見抜く決め手に
なった。ケーブル長(2m=往復20ns)では546nsの周期は説明できない点も一致する。

### 定数の選び方

TVPの入力容量10pF(データシート CI)が並列に入る。

| C(外付け) | 実効 | 遮断周波数 | 備考 |
|---|---|---|---|
| 15pF | 25pF | 28.9MHz | 試作で実測した値 |
| **33pF** | **43pF** | **16.8MHz** | 採用値 |
| 47pF | 57pF | 12.7MHz | さらに折り返しを削るが最細部が鈍る |

採用値の16.8MHzは、最も高いモード(31kHz 768ドット、ドットクロック34.78MHz)の
ナイキスト17.4MHzにほぼ一致する。隣接ドットが交互に変わる最細パターンは3dB
落ちるが、それはそもそも折り返す成分なので抑えるのが正しい。鮮鋭さを優先するなら
15〜22pFに下げる。

**c_aa は TVP の入力ピン直近に置くこと。** r_aa は結合コンデンサの直後で構わない。
R/G/B の3チャンネルとも同じ値にする(片方だけ違うと色ずれになる)。

### 補足: ビーズは使わないこと

映像信号にフェライトビーズを入れると、低周波ではインダクタとして振る舞うため
コンデンサとLC共振を作り、まさにここで消したリンギングを自分で作り込むことに
なる。ビーズは電源ライン専用。

### 未使用アナログ入力(基板設計では対応済み)

データシートは未使用のアナログ入力を10nFで、未使用SOG入力を1nFでGNDへ落とすよう
指定している。**main.ato では対応済み**(nc_caps × 7、nc_sog_caps × 2)。手半田の
試作機に無いだけなので、基板を起こせば解消する。

## TVP7002のレジスタ設定(実測で決めたもの)

初期化で書いている値のうち、**実測で効果を確認して決めた**ものを記録する。
どれも既定値のままでは症状が出る。

### 3Fh = 0Fh (アナログ映像帯域を最小に)

外付けRC(28.9MHz)を入れてもエッジの直後に残っていた**1つ目のエコー**が消える。

| 3Fh | 残留エコー(明線直後の超過) |
|---|---|
| 00h(最大帯域・既定) | +2.55 |
| 08h | +1.82 |
| 0Ch | +1.01 |
| **0Fh(最小≈95MHz)** | **+0.01** |

単調に減り、戻すと再現する。外付けが28.9MHzで切っているので効かないと予想したが
実際には完全に消えた。残留エコーの成分が95MHz以上にあり、単極RCでは95MHzを10dB
しか落とせなかったためと考えられる。

代償はエッジの立ち上がり(2サンプル=58ns)が変わらないまま、最細部の振幅が6%
落ちるだけ。

### 2Ah = 87h (ファインクランプのCMオフセットを有効に)

白ベタ領域の**先頭20サンプル(約576ns)だけ2〜3%暗くなる**症状が、GとBにだけ
出ていた(Rには出ない)。データシートで 2Ah は `Fine GB`(G/B共通)と `Fine R`
が別ビットになっており、症状の出方と一致した。

| 2Ah | R | G | B |
|---|---|---|---|
| 07h(既定) | +0.2 | +2.6 | +2.0 |
| 0Fh/17h/1Fh(時定数を短く) | +0.2 | +2.6 | +2.0 |
| **87h(CM Offset 有効)** | +0.1 | **+2.2** | **+0.3** |

**時定数(bit[4:3])は全く効かなかった**。効いたのは CM Offset(bit7)で、
データシートの "can be enabled to improve isolation and channel crosstalk" の
とおり、原因はクランプの応答ではなく**チャンネル間のクロストーク**だった。
白レベルは 102.7% → 102.8% で副作用は見られない。

### 残件: Green の +2.2%

Blue はほぼ解消したが Green に +2.2% が残っている。

測定した試作機は手半田で、**Green だけ信号線が長い**。切り分けの結果、これが
残差の原因と考えられる。

| 検証 | 結果 |
|---|---|
| X68000側で G と B を入れ替え | **症状は G のまま移らない** → 信号源は無罪 |
| 3chの立ち上がり時間 | 1.50サンプルで完全一致 → 部品値・半田付けに差なし |
| Green の AGND を最短化 | 変化なし |
| SOGIN_3(未配線)に0.01µF追加 | 変化なし |
| クランプ時定数 (2Ah bit[4:3]) | 変化なし |

信号を入れ替えても症状が基板の Green 経路に留まることから、**基板側で拾っている**
と判断できる。部品も設定も対称なので、残る非対称は配線長だけ。

CM Offset の効き方もこれで説明できる。あれは TVP 内部の分離を改善するものなので、
チップ内で完結する分(Blue)は解消したが、**基板上で拾っている分(Green)には
効かなかった**。

**基板を起こして3本を短く等長にすれば消える見込み**なので、この数字を基板設計の
判断材料にしないこと。基板版でも残る場合は、SOGスライサの停止(2Bh bit6)を試す
価値がある(未検証)。ただし将来 SOG 入力に対応する際に必要な経路なので、無効化
するなら実行時に切り替えられる形にすること。

### 効かなかった/悪化した設定(再調査を避けるための記録)

**03h(VCOレンジ+チャージポンプ)** — TVP既定 A8h は VCO Medium(70〜135MHz用)で、
こちらのピクセルクロック(8.7〜44MHz)とは規定範囲が合っていない。データシートどおり
Ultra low + ICP=3 の 18h にして実測したが、**効果が無かった**。

**05h/06h(クランプ開始/幅)** — データシート Table 13 の PC graphics 推奨は 06h/10h
だが、**ノイズが3割悪化する**。落ち込みは僅かに改善する(G +1.5 → +1.1)が割に合わない。
推奨値はクランプ窓が狭く黒レベルの平均化が減るため。X68000のバックポーチは一般的な
PCより長いので、既定の広い窓(開始50・幅32)の方が有利だった。
**データシートの推奨がそのまま最適とは限らない例。**

31kHz 256x256(pll 1104)での実測。同じ並びを電源条件を変えて2回測り、いずれも同じ
関係になった。

| 条件 | ノイズ | R | G | B |
|---|---|---|---|---|
| 既定 A8h/32h/20h | **3.33%** | +0.7 | +1.5 | +0.9 |
| 03h=18h のみ | 3.28% | +0.7 | +1.4 | +0.9 |
| 05h/06h=06h/10h のみ | **4.41%** | +0.6 | +1.1 | +0.7 |
| 両方 | 4.65% | +0.7 | +1.1 | +0.7 |
| 既定に戻す(再現確認) | 3.24% | +0.7 | +1.5 | +0.9 |

**測定時の注意**: ノイズの絶対値は電源で大きく動く(下記)ので、条件間は必ず連続して
測り、最後に基準へ戻して再現を確認すること。また設定が本当に届いたかを毎回確認する
こと(CONFIG応答を見る)。**古いファームでキーが未対応だと設定が黙って無視され、
「効果なし」に見える**。実際それで一度誤った結論を出しかけた。

### ノイズは電源に強く依存する ← PCB設計で最重要

同じ設定・同じモードで、USBの接続経路を変えただけでノイズが3倍動いた。

```
1.1%  〜  3.3%  〜  3.9%     (接続経路の違いだけ)
```

試作時はUSBハブが4〜5段に連なっており、段数や挿す位置で電源の質が変わっていた。
レジスタ設定をいくら詰めても、この振れ幅の方がはるかに大きい。**基板では電源の質を
最優先すること**(アナログ電源の分離、デカップリング、USBから引く場合の経路)。
評価するときは電源条件を固定し、変えたら基準値を取り直すこと。

### 実行時に変更できる

切り分けのため CONFIG で変えられるようにしてある(ビルドし直さずにA/Bできる)。

| key | 対象 |
|---|---|
| 0x17 | 3Fh 映像帯域 (0〜15) |
| 0x18 | 2Ah ファインクランプ (8bit) |
| 0x19 | 03h PLL(VCOレンジ+チャージポンプ) |
| 0x1A | 05h クランプ開始位置 |
| 0x1B | 06h クランプ幅 |
