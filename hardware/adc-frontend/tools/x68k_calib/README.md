# X68000 校正パターン FD イメージ

ADC(TVP7002)のゲイン・オフセットを合わせるためのテストパターンを、
**Human68k を介さずフロッピーのブートセクタから直接起動**して表示する。

XEiJ で動作確認済み(2026-09-02)。

## 作る / 動かす

```sh
make            # calib.xdf (1,261,568バイト = 2HD の生セクタ列) を作る
make run        # XEiJ で FD0 から起動して確認
make check      # ツールチェーンのパスが通っているかだけ見る
```

ツールチェーンは `X68000_MSX_Simulator` と同じ流儀。ソースは UTF-8 で管理し、
HAS060 が要求する CP932 へ変換したシャドウを `build/` に作ってからアセンブルする。
パスは `~/.human68k.mk` か `local.mk` で上書きできる。

```
calib.has --(CP932変換)--> build/calib.has --(run68 HAS060.X)--> build/calib.o
          --(run68 hlk.x)--> build/calib.x --(mkxdf.py)--> calib.xdf
```

## 画面の構成(512x512 / 65536色)

| 行 | 内容 | 目的 |
|---|---|---|
| 0-63 | グレー32段(各16px幅) | ゲイン・オフセットの同時校正 |
| 64-127 | 赤32段 | R チャンネル単独 |
| 128-191 | 緑32段 | G チャンネル単独 |
| 192-255 | 青32段 | B チャンネル単独 |
| 256-319 | 1px幅の白/黒縦縞 | ドット復元(逆フィルタ)の検証 |
| 320-383 | 2px幅 | 同 |
| 384-447 | 4px幅 | 同 |
| 448-511 | 左半分白 / 右半分黒 | 白レベルと黒レベルの基準 |

65536色モードは 1ワードが `GGGGG RRRRR BBBBB I` なので、**パレットを介さず
5bit×3 を直接指定できる**。階調 n は `(n<<11)|(n<<6)|(n<<1)`(I=0)で、
X68000 本来の32階調をそのまま出せる。

## 読み方

| 見えるもの | 意味 |
|---|---|
| 階調の**抜け**(コードが飛ぶ) | ゲインが高すぎる |
| 階調の**重複**(隣接段が同じコード) | ゲインが低すぎる |
| 上端だけ重複 | クリップしている |
| 32段が32コードに載る | **ロスレスが成立している証拠** |

★このモードは 768x512 のテキスト画面と **pll_div が違う**。Viewer の
「→ 適用」(実測 fH から htotal を算出)か「自動調整」で合わせ直すこと。

## ブートセクタとして守るべき制約

IPL ROM は「論理セクタ0の 1024 バイトを `$002000` へ読み、そこから実行」
するだけなので、以下は破ると黙って動かなくなる。`mkxdf.py` が機械的に検査する。

- **先頭命令は BRA.B / BRA.W**(先頭バイトが `$60`)
- **1 セクタ(1024B)以内**。超えるなら自分で追加セクタを読む処理が要る
- **再配置が無いこと = 完全に PC 相対で書く。** HLK の既定ベースは `$002000`
  ではないので、絶対アドレスのラベル参照が残ると壊れる。ハードウェアアドレス
  (`$C00000` 等)は即値なので対象外
- **実行開始が先頭と一致していること**
