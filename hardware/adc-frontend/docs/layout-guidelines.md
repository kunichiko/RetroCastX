# RetroCastX ADCフロントエンド レイアウト指示書

TVP7002混載(アナログRGB + 高速デジタル + GbE + 音声)基板のPCBレイアウト方針。
KiCadでの配置・配線はこの指示書に沿って行う。根拠は各部データシート + OSSC rev1.8 +
kazkojima i5ether。回路は `main.ato`、ネットリスト/PCBは `ato build` が生成(配置は保持される)。

---

## 0. 基板全体・スタックアップ・グラウンド

- **層構成: 4層 1.6mm を設定済み**(`default.kicad_pcb` の physical stackup)。
  L1=F.Cu(信号) / **L2=In1.Cu(GNDプレーン)** / **L3=In2.Cu(PWRプレーン)** / L4=B.Cu(信号)。
  スタックアップは **JLCPCB JLC04161H-7628 相当**: L1-L2間プリプレグ=7628 **0.2104mm**(εr 4.6)、
  コア 1.065mm、内層銅 0.5oz(0.0152mm)、外層銅 1oz(0.035mm)、ENIG。上部プリプレグを厚い7628に
  したのは、GbE 100Ω差動をL1で実用的なトレース幅(≈0.2mm)で引けるようにするため(3313の0.1mmだと
  0.09mm級の細線が必要で歩留まり悪化)。★JLC発注時にこのスタックアップを明示指定すること。
  **`ato build` はこのスタックアップ設定を保持する**(検証済み)。
  GbE差動ペアとDATACLK(~80MHz)の特性インピーダンス制御と、L2ベタGNDによる
  リターン経路確保のため。2層では高速系の品質確保が困難。
- **グラウンド: L2 を極力ベタの単一GNDプレーンにする**(分割しない)。混載基板は
  「面分割」より「**配置で分離**」が現代的ベストプラクティス。
  - アナログ区画(D-SUB15→前段→TVPアナログ電源側)とデジタル区画(TVPデジタル出力→
    スタッキングヘッダ)を**物理的に左右で分け**、デジタルのリターン電流がアナログ入力の
    下を通らないようにする。
  - GbE磁気部の下は**GND/電源プレーンをくり抜き**(keepout)、シャーシGNDと論理GNDを
    その部分だけ分離(絶縁ギャップ、下記6章)。
- **TVP7002の露出パッド(EP, pin101)は直下に多数のサーマルビアでL2 GNDへ**(熱+電気)。
- 基板外形は**仮120×90mm**。★EXT基板実寸(P1/P2/P4ヘッダ位置・間隔、i5モジュール高さ、
  ソケット嵌合高さ≈11mm)で確定させること。スタッキングヘッダ3本がEXTと1対1で嵌合する
  位置が最優先の物理拘束。

## 0.5 SO-DIMMソケット(U11)— 水平(寝かせ)タイプ / 2026-08 差し替え

以前は JST DM-7D4-H2500(M)(C483268)のフットプリントを流用していたが、これは
**モジュールが基板に垂直に立つタイプ**だった。本設計は i5 モジュールを**基板と平行に
寝かせる**前提(JTAGとPHY LEDをモジュール底面パッドへポゴピンでバネ接触させるため)なので、
水平タイプ(right angle module orientation)の実部品へ差し替えた。

型番は [hansfbaier/colorlight-qmtech-adapter](https://github.com/hansfbaier/colorlight-qmtech-adapter)
の JLCPCB 発注用BOM から判明した(`1473005-4,CN1,...,C428482`)。

**採用部品: TE 1473005-4 (LCSC C428482, 在庫1636・$4.48)**。ベンダ純正フットプリントを
`tools/ingest_parts.py` で取り込んだ(ラッチ保持パッド・非対称位置決め穴・STEP付き)。

| 項目 | 垂直(旧流用) | TE 1473005-4(採用) |
|---|---|---|
| 列間 | 6.6mm | **8.60mm** |
| パッド | 2.0 × 0.4mm | 0.35 × 2.0mm |
| 列内ピッチ / 列間ずれ | 0.6 / 0.3mm | 同じ(MO-224) |
| span | 63.00mm + キー切欠4.2mm | 同じ |
| ラッチ保持SMDパッド | なし | **4.5 × 4.6mm ×2**(pad名201)→ GND |
| 位置決め穴 | φ1.05/φ1.45(垂直部品のもの) | **φ1.6 / φ1.1 の非対称**(向き間違い防止) |
| ボディ | — | **71.5 × 26 × 5.2mm**(STEP) |

★列間について: TE 1717254-1 の仕様表の "Reihenabstand 6.2mm" は**基板ランドの列間では
なかった**。実フットプリント3件(TE 1473005-4=8.60 / TE 1473149-4=8.20 / KiCad標準の
DDR4版=8.20mm)で確定。**1473149-4 と 1473005-4 はランドが違うので、買う型番と一致させること。**

### モジュールが基板を覆う(最重要の物理制約)

寝かせると i5 モジュールが基板の上に張り出す。**Colorlight i5 は 68 × 36mm** で、
JEDEC標準の SO-DIMM モジュール(67.6 × 30mm)より **6mm 深い**。SO-DIMMエッジコネクタを
使っているだけの独自寸法のモジュールなので、MO-224 の 30mm で見積もると足りない。

ソケット本体は **71.5 × 26 × 5.2mm**(取り込んだSTEPより)。

- **モジュール下に入る部品はスタックハイト(5.2mm)より低くしなければならない**。
  電解コンデンサや背の高いコネクタは置けない
- **ポゴピン(PG1-4=JTAG, PG5-8=PHY LED)の自由長3mm が届くかを必ず確認**。
  mech.ato は「モジュール裏〜基板間隙 2.6mm → 約0.4mm圧縮」を想定しているが、
  採用品のスタックハイトは5.2mmなので**そのままでは届かない可能性が高い**。
  長いポゴピンにするか4.0mm品のソケットにするかを実測で決める。
  届かないと**JTAG書き込みとPHY LEDの両方が成立しない**
- モジュールが寝る方向はフットプリントのローカル+x(下記「向きと配置」)。配置時の
  回転で決まるので、**モジュールが盤外へはみ出さない向き**にし、覆われる区画を意図的に選ぶ
- STEPが付いているので **3Dビューアでモジュール下のクリアランスを目視確認できる**

### 向きと配置

フットプリントのローカル座標では**信号列が y 方向**に並ぶ(x=−8.1 が奇数ピン、
x=+0.5 が偶数ピン、ラッチパッドが x=+8.1、位置決め穴が x=−3.9)。
シルクは **x −9.0〜+17.0**(=ボディ26mm)なので、**モジュールは +x 方向へ寝る**。
本設計では U11 を回転させて使うので、盤外へモジュールがはみ出さない向きを選ぶこと。

### ★発注前に確認すること

1. **スタックハイト 5.2mm とポゴピンの整合**: `mech.ato` は「モジュール裏〜基板間隙
   2.6mm・ポゴピン自由長3mm」を想定している。**5.2mm品ではポゴピンが届かない可能性が
   高い**。長いポゴピンに変えるか、4.0mm品のソケットにするかを実測で決める。
   JTAGだけでなく**PHY LEDタップ(PG5-8)も同じ問題**を持つ
2. **買う型番とランドの一致**: 汎用品で代替する場合、列間8.60mm・ラッチパッド位置・
   位置決め穴径(φ1.6/φ1.1の非対称)を実測で確認する
3. **JLCの実装ライブラリ収載は未確認**。実装対象外なら手はんだになるが、
   200本0.6mmピッチなので極力JLCに実装させたい

## 1. 配置の大方針(信号の流れ)

```
[左辺] 映像入力(D-SUB15 / 2x8) → [中央左] アナログ前段 → [中央] TVP7002
   → [下辺] スタッキングヘッダ(FPGAへ24bit+DATACLK)
   → [右辺] GbE(MagJack×2)
[上辺] 電源(USB-C/DC) と 音声(PCM1808/XO/ジャック/TOSLINK)
```
- 映像は左→右へ一方向に流し、アナログ入力とデジタル出力を離す。
- 電源は上辺にまとめ、各レールを各負荷へ最短で分配。
- **クリティカルネット優先度: ① GbE MDIペア ② TVP DATACLK(ドットクロック~80MHz)
  ③ アナログRGB入力 ④ 音声MCLK(12.288MHz)**。この順で最短・最良の経路を確保。

## 2. ネットクラス / 線幅 / クリアランス

**設定済み**(`layouts/default/default.kicad_pro`、`net_settings.classes` + `netclass_patterns`)。
`ato build` はこの `.kicad_pro` を上書きしないので設定は保持される。

| ネットクラス | 線幅(既定) | クリアランス(下限) | ビア | 差動幅/ギャップ | 割当パターン(実ネット名) |
|---|---|---|---|---|---|
| Default | 0.20mm | **0.127mm** | 0.45/0.25 | — | 上記以外すべて |
| Power | 0.40mm | 0.20mm | 0.8/0.4 | — | `power_5v*` `p5v_ext` `p3v3_io*` `p3v3_a*` `p3v3_ext` `p1v9_a*` `p1v9_d*` `hdr_p4-p3v3_ext` |
| GbE_diff | 0.20mm | 0.40mm | 0.45/0.25 | **0.20/0.13mm** | `eth1_*` `eth2_*` (8ペア) |
| Analog_RGB | 0.25mm | 0.30mm | 0.45/0.25 | — | `vin_*` `rin3` `gin3` `bin3` `sogin3` |
| Clock | 0.25mm | 0.25mm | 0.45/0.25 | — | `dataclk` `ext_clk` `audio_mclk` `audio_bck` `audio_lrck` |

**「線幅」は新規配線時の既定値、「クリアランス」はDRCが見る下限**という違いに注意。
太さは配線しながら `W`キーで候補から切り替えられる(候補:
0.1 / 0.127 / 0.15 / 0.2 / 0.25 / 0.4 / 0.6 / 0.8mm)。ビアも `V`キーで
0.45/0.25(ファンアウト用)・0.6/0.3(汎用)・0.8/0.4(電源)から選べる。

### 微細ピッチの引き出し(2026-08 更新)

**旧設定(Default クリアランス0.20mm・ビア0.6/0.3)では 0.5mmピッチQFPと
0.6mmピッチSO-DIMMからファンアウトできなかった**ので、JLCPCB 4層の実能力に合わせて
下限を緩めた。数字の根拠は
[JLCPCB PCB capabilities](https://jlcpcb.com/capabilities/pcb-capabilities)(2026-08確認):

| 項目 | JLC 4層の下限 | 本基板の設定 | 備考 |
|---|---|---|---|
| 線幅 / 間隔 | 0.09 / 0.09mm | 0.10mm(基板最小値) | ネットクラス下限は 0.127mm(5mil) |
| ビア 穴 / 径 | 0.15 / 0.25mm | **0.25 / 0.45mm** | 「穴0.15mm」「穴0.2-0.25mmで径0.45mm未満」は**追加費用**。0.25/0.45が無償の下限 |
| ビア穴間 | 0.20mm | 0.20mm | 基板最小値 min_hole_to_hole |
| PTHパッド穴間 | 0.45mm | 0.45mm | KiCadは穴間を1種類しか持てないので `.kicad_dru` 側で Pad-Pad のみ0.45mmに戻す |
| 銅-基板外形 | ≧0.20mm | 0.25mm | **旧設定は0.5mmで過剰**。基板端の配線が通らなかった |
| シルク 線幅 / 文字高 | 0.15mm / 1.0mm | 0.15mm / 1.0mm | |

実際に通るかの計算(いずれもDefaultクラス):

- **0.5mmピッチQFP**(パッド幅0.28mm, 隣接パッド間0.22mm)
  - パッドから真っ直ぐ外へ: 0.15mm線 → 隣パッドまで 0.36-0.075 = **0.285mm** ✓
  - **パッドの間を通り抜けることは不可**(0.127線でも0.381mm必要 > 0.22mm)。
    内側のピンは外周へ出したあとビアで落とす(ドッグボーン)
  - ビアは0.5mmピッチに1列では入らない(0.45+0.127=0.577mm必要)ので**2列に千鳥**
- **0.6mmピッチSO-DIMM**(パッド幅0.4mm)
  - 0.15mm線で真っ直ぐ: 隣パッドまで 0.4-0.075 = **0.325mm** ✓
  - ビアは0.6mmピッチの1列でぎりぎり合法(0.577mm ≤ 0.6mm、穴間0.35mm ≥ 0.2mm)
- **電源(Power)の 0.4mm線は 0.5mmピッチパッドから直接出せない**
  (0.36-0.2 = 0.16mm < 0.20mm)。**パッド直近だけ0.2mmでネックダウンしてから広げる**

### ゾーン(GNDベタ)のクリアランス

新規ゾーンの既定クリアランスを **0.5mm → 0.25mm** にした。0.5mmだとベタが引っ込み過ぎて
微細ピッチ部品の下でリターン経路が切れる。**既存の4つのゾーン(F.Cu gnd / F.Cu chassis /
In2.Cu p3v3_a / In2.Cu p3v3_io)は個別に0.5mmを持っているので、pcbnew上で
それぞれのプロパティを0.25mmに変更すること**(既定値の変更は新規ゾーンにしか効かない)。

- **差動ペア認識**: GbEネットは `+/-` でなく大文字 `_P`/`_N` 接尾辞(例 `eth1_1_P`/`eth1_1_N`)。
  KiCadの差動ペアルータ(ホットキー`6`)/DRC結合チェックは `+/-` か大文字 `P/N` のみ認識するため、
  main.ato/mech.ato側で小文字→大文字化済み。8ペア(eth1_1〜eth1_4=ポート1, eth2_1〜eth2_4=ポート2)。
- **GbE_diff 差動幅/ギャップ 0.20/0.13mm** = 設定済みスタックアップ(H=0.2104mm/εr4.6)での
  エッジ結合マイクロストリップ解析値 ≈100Ω(W0.2/S0.13→99Ω, W0.2/S0.15→102Ω)。
  ★解析値なので**配線前にJLCの[インピーダンス計算](https://jlcpcb.com/impedance)またはKiCad内蔵の
  インピーダンス計算(Board Setup>Physical Stackup、スタックアップ設定済みなので即使える)で最終確認**すること。
- **カスタムDRC設定済み**(`default.kicad_dru`): GbEペア内スキュー≤0.15mm、非結合区間≤5mm、
  ビア数≤2/本、対他ネットクリアランス≥0.6mm、クロックのビア数≤3。配線するとこれらが自動チェックされる。
- **Analog_RGBネット名の対応**(atopileがパッシブのpowerインターフェース名で命名):
  R入力=`c_ac-power-hv`, B入力=`c_ac-power-hv-1`, G入力=`c_sog3-power-hv`,
  R/G/B出力(TVP側)=`c_ac-power-lv{,-1,-2}`, SOG=`c_sog3-power-lv`。
- SYNC(`hsync`/`vsync`/`hsync_a`/`hsout`/`vsout`/`fidout`)はDefault。長くなければ問題ない。
- 電源はできるだけ**L3プレーンのゾーン**で供給し、トレースは引き出しのみ。
- 高速信号(GbE/DATACLK)は**層をまたがない**(またぐ場合は隣接にGNDリターンビア)。

## 3. アナログRGB前段(D-SUB15 直近)

- **75Ω終端(R75)と100nF ACカップリング(C100nF)は D-SUB15 のR/G/Bピン直近**に置く。
  順序: コネクタ → ESD(EsdArray4) → 75Ω終端(→アナログGND) → 100nF直列 → TVP RIN_3/GIN_3/BIN_3。
- **ESDアレイ(ROHM EMZT6.8)は各入力をコネクタに最も近い位置**で保護(ストレス経路最短)。
- 緑のSOGカップリング(1nF)はGIN経路の近く。
- RGB3本は**等長・並走・周囲をアナロググラウンドでガード**。ビアを避け極力L1で。
- この区画のGNDはアナロググラウンド。デジタル出力(下辺)から遠ざける。

## 4. TVP7002(中央)

- **各電源ピン群に100nFデカップリングを"そのピンの直近"に**(合計14個, `dec_caps`)。
  ピンとキャップの間のループ面積を最小化。A33VDD/AVDD/PLL_AVDD/DVDD/IOVDDそれぞれ。
- **AVDD/PLL_AVDDのフェライトビーズ(fb_avdd/fb_pll)はTVP側**に置き、1.9Vアナログから分離。
- **H-PLLループフィルタ(r_filt 1.5k, c_filt1 100nF, c_filt2 4.7nF)は FILT1/FILT2/PLL_F
  (pin87/88/89)の直近**。ここが最も敏感。ループを小さく、他の信号から隔離。
- EP(pin101)→サーマルビア→GND(0章)。
- **デジタル出力(R/G/B[9:2] 24本 + DATACLK + HSOUT/VSOUT/SOGOUT/FIDOUT)は
  TVPの出力側(pin29-65側)から下辺のスタッキングヘッダ(hdr_p2/hdr_p4)へ短く**。
  **DATACLK(pin28→hdr_p4 F2/PCLKT7_0)は最短・直下GND連続**。
- 制御抵抗(r_i2ca/r_sda/r_scl/r_rst 各2.2k)とI2CはTVPの制御側(pin70-77)近く。
- 27MHz OSC(osc)+デカップリング(c_osc)は EXT_CLK(pin80)近く。

## 5. 同期(SYNC)

- 同期ESD(esd_sync)は D-SUB15 のHSYNC/VSYNCピン直近。
- VSYNC RC遅延(r_vs 220Ω + c_vs 1nF)とバッファ(LVC2G17)は同期経路上、TVPに近い側。
- バッファのVCCデカップリング(c_buf 100nF)はLVC2G17直近。

## 6. GbE(右辺・MagJack×2)

- **MagJack(HR911130A)は基板端**に開口を外へ向けて配置。J8(P1)からMDIペアを最短で。
- **MDI0-3±は差動ペア(GbE_diff)。ペア内で等長、短く、直線的に**。EXT P1(j8)から
  各MagJackへ。ペアの下はL2 GND連続。
- **チップ側センタータップ共通(P1ピン)→ 0.1µF → 論理GND**(各ポート1個、MagJack直近)。
- **P10(Bob-Smith/シャーシ基準)と SHIELD0/1 → シャーシGND**。
- **磁気部の下は論理GND/電源プレーンをくり抜き(keepout)**、シャーシGNDアイランドを作る。
- **論理GND ⇄ シャーシGND 間は 4.7nF/2kV(各ポート2個)で結合**(HV Yキャップ、
  絶縁ギャップをまたいで配置)。沿面/空間距離を確保。
- LED(pin11-14)はP1に信号が来ていないため未接続(配線不要)。

## 7. 電源(上辺)

- **入力**: USB-C(J10相当, CCにRd 5.1k×2をコネクタ直近)/ DCジャック。SJ1でEXTへ逆給電。
- **AZ1117-ADJ(1.9Vアナログ, ldo_a19)は約0.9W発熱** → SOT-223タブ下に**銅箔ベタ+
  サーマルビア**。他の熱源(他LDO)と離す。分圧抵抗(r_fb_top 120Ω/r_fb_bot 62Ω)は
  ADJピン直近(ノイズ拾い防止)。
- 各LDO入出力のバルクコン(10µF)はLDO直近。レール別に負荷へ最短分配。
- レール整理: 5V→{IO 3.3V(ldo_io), アナログ3.3V(ldo_a33), 1.9Vアナログ(ldo_a19)},
  IO 3.3V→1.9Vデジタル(ldo_d19, TLV70019)。**アナログ系LDOはアナログ区画寄り**に置く。

## 8. 音声(上辺〜中央上)

- **PCM1808×2(adc_dsub/adc_line)**: 入力ACカップリング(1µF)を各入力直近、VREFデカップ
  (10µF+100nF)を各ADC直近。
- **12.288MHz XO(xo_audio)は両ADCのSCKIに近接**し、MCLK配線を短く(クロックネットクラス)。
  BCK/LRCKはFPGA(hdr_p4)から。DOUTは個別にhdr_p4へ。
- 音声アナログ5V(fb_audioでデジタル5Vから分離, c_5va 10µF)はADC VCCへ。
- 音声入力のESD(esd_audio)はジャック/コネクタ直近。
- **音声区画は電源スイッチング系やデジタルから離す**(ハム/ノイズ対策)。

## 9. TOSLINK(PLR135, 手実装)

- **C1(c_spdif 100nF)は Vcc-GND 間、TOSLINKの7mm以内**(データシート必須要件)。
- ★**L2=47µH(電源直列)が現設計に未実装**。データシート推奨。追加を検討
  (Vcc直列にフェライト/インダクタ。ノイズ源からの絶縁)。→ main.ato修正候補。
- 光受信は感度が高いので、高速デジタル/スイッチングから離す。

## 9.5 デジタルRGB入力(J13 + U14/U15/U16 + D4/D5)— 2026-08 追加

```
J13(1.25mm 8極, 基板端) → D4/D5(ESD) → 10kプルダウン → U14/U15/U16(LVC2G17) → SO-DIMM P4クラスタ
```

- **J13 は基板端**にコネクタ開口を外向きに。右アングルSMDなのでケーブルは横に出る。
  取付タブ(pad9/10)はGNDに落とす=実装強度を稼ぐので、GNDベタに接続すること
- **D4/D5(ESD)は J13 直近**。保護はストレス経路が短いほど効く(アナログ側と同じ方針)
- **U14/U15/U16 は J13 とSO-DIMMの間**に置く。5V TTLが基板上を長く走らないよう
  **バッファはコネクタ寄り**に置き、バッファ後の3.3V信号でSO-DIMMまで引く
- **各バッファのVCCデカップリング100nFはIC直近**(3個)
- **5V TTL区間(`drgbi_*`)をアナログRGB前段・音声アナログと並走させない**。
  ドットクロック速度(最大14MHz程度)でフルスイングするので、
  アナログRGB入力(§3)からは物理的に離す。デジタル区画側に寄せて配置する
- 3.3V側(`drgb_*`)6本はDefaultクラスで可。等長は不要(FPGA内でオーバーサンプリング
  するので数百ps差は無関係)。ただし **HS/VS は色4bitと束ねず、GNDを隣に添えて引く**
  (同期を1回取り落とすと1フレーム崩れる)
- SO-DIMM側の受けは pin132/136/140/142/144/146 = P4クラスタの偶数側。
  ソケット上で x方向に連続して並ぶので、6本まとめて素直に引ける

## 9.6 将来拡張用デバッグ端子(J4, 2×15)— 2026-08 追加

- 引き出すのは **SO-DIMM 偶数側 pin54〜94**(pin56=GNDのみ除く)の20本。
  ソケット上で **x=146.8〜158.8mm・y=103.0mm** に0.6mmピッチで一列に並ぶ
  (ソケット原点 146.65,99.70 / 180°回転時の実測値)
- **SO-DIMM昇順 ↔ ヘッダpin昇順の単調割当**にしてあるので、素直に扇形に広げれば
  交差は出ない。ヘッダは**ソケットの下側(y>103の領域)**に置くのが最短
- 近傍の既存部品: X2(音声XO, 157.3/101.8)・U4/U5(EEPROM, 155.9/111.6 と 165.4/112.2)・
  U8(TLV70019, 146.3/112.9)。**X2(12.288MHz)の直下を20本で横切らないこと**
  (音声MCLKにデジタルノイズが乗る)。ヘッダはこれらより下(y≈125〜140)に置き、
  X2の下を避けて左右どちらかに寄せて通す
- 2×15の外形は 35.6×5.1mm(パッド中心間)。基板の下辺側(y=149)までは余裕がある
- **未使用のままでも構わない**(手実装/DNP)。基板にパッドさえあれば後から生えてくる

## 9.7 Ethernet LED の二経路(PG5-8 / JP4-7)— 2026-08-11 追加

```
経路A(既定) i5モジュール底面PHY LEDパッド → ポゴピン(PG5-8) → 220Ω(R27-30) → MagJack pin11/14
経路B(代替) FPGA GPIO → はんだジャンパ(JP4-7, 既定=開) → 220Ω(R16-19) → 同じアノード
```

- **ポゴピン位置は rainbow-board の実測値**(SO-DIMMソケット原点からの相対):
  JTAG 1×04 = (−24.15, −33.30) / ETH1 LEDs = (−22.08, −29.59) / ETH2 LEDs = (−22.15, −15.43)。
  JTAGの縦33mmが本設計の既存想定と一致したので座標系は信用できる。
  **rainbowのソケット向き基準なので、本設計の回転に合わせて置き換えること**
- ポゴピンはモジュール下(=モジュールが覆う領域)に入るので、**周囲に背の高い部品を置かない**
- **JP4-7 は手が届く位置に**(既定=開。閉じてGPIO経路に切り替える運用があるため)
- ★**両経路を同時に生かさないこと**。アノードで押し合う(≒7.5mA)。
  経路A運用時はゲートウェアでGPIO(io_r1/io_t1/io_u1/io_y2)を入力にしておく

## 12. 作業手順(推奨)

1. EXT採寸 → スタッキングヘッダ3本と基板外形を確定。
2. 外部コネクタを基板端に配置(開口方向確定)。
3. TVP7002を中央に、上記ブロックを1〜10の近接ルールで配置。
4. GNDプレーン(L2)敷設、GbE磁気部keepout/シャーシアイランド作成。
5. 配線: ①GbEペア ②DATACLK ③アナログRGB ④音声MCLK → 残り。
6. `kicad-cli pcb drc` でDRC。ネットクラス/差動ペア/クリアランス違反を潰す。
7. `ato build` で回路変更を反映(配置は保持)。差分は都度DRC再確認。

### ★`ato build` と pcbnew を同時に開かないこと

**`ato build` は必ず `default.kicad_pcb` を書き換える**(`--exclude-target pcb` を
付けても "Updating PCB" ステージは走る。ターゲット指定では止められない)。
pcbnew が同じファイルを開いたままだと:

- pcbnew はメモリ上の**古い**基板を保持している
- そこで保存すると **atopile が追加した部品・ネットが消える**
- `~default.kicad_pcb.lck` は単なる助言でロックにはならない

手順を守る:

1. pcbnew で**保存して閉じる**
2. `ato build` を実行
3. pcbnew を開き直す(`File > Revert` でも可)

**フットプリントを差し替えたときは `ato build` を2回流すこと。** 1回目は基板上の
フットプリントを新しいものに置き換えるだけで、**そのパッドにネットが付かない**
(実測: U11差し替え直後は 123あったネット割当が0になった)。2回目で復帰する。
1回目の状態で保存/配線すると、ソケットが全ピン未接続に見える。

また**パッド位置が動いた差し替えでは、既存のゾーン塗りが古くなる**。U11の列間を
6.6→6.2mmにした直後、`clearance` 違反が 70→247件に増えたが、その +177件は全て
「古い塗りとパッドの距離不足」だった(ゾーン再フィルで70件に戻ることを検証済み)。
**pcbnew で `B` を押してゾーンを再フィルする**こと。あわせて既存4ゾーンの
クリアランスを 0.5→0.25mm にする(§2 のゾーン項参照)。

`ato build` が部品を追加した場合、新規フットプリントは**基板外(y=0近辺)に置かれる**ので
そこから盤内へドラッグする。既存部品の座標・配線・ゾーン・スタックアップ・
`.kicad_pro`(ネットクラス)・`.kicad_dru` は保持される(検証済み)。
なお `tools/ingest_parts.py` で部品を取り込むと `fp-lib-table` が更新されるため、
その場合も **pcbnew の再起動が必要**(atopile自身がそう警告する)。

### DRCの読み方(2026-08 時点の既知の残件)

未配置・未配線の段階では大量に出る。**配置/配線で自然に消えるもの**と
**発注前に必ず潰すもの**を分けて見る。

| 種別 | 数 | 位置づけ |
|---|---|---|
| `silk_overlap` / `silk_over_copper` / `silk_edge_clearance` | 199/146/27 | 見た目のみ。最後にリファレンス文字を整理する |
| `shorting_items` / `clearance` / `solder_mask_bridge` | 38/70/55 | 大半は**基板外に積まれた未配置部品の重なり**。配置後に再評価する |
| `starved_thermal` / `isolated_copper` | 16/8 | ゾーン敷設のやり直しで解消する |
| `copper_edge_clearance` | 5 | **要対応**: J9(USB-C) pad2/3・J2 SHIELD0 が外形から0.176mm(JLC下限0.2mm)。数十µm内側へ寄せる |
| `text_height` | 1 | **要対応**: 0.8mmのシルク文字が1つ(JLC下限1.0mm)。1.0mmに直す |
| U11パッドとの重なり | — | **要対応**: **C3(音声VREFコンデンサ)が U11 のパッド上に完全に重なっている**(距離0.000mm)。X2(12.288MHz XO)もU11パッドに近すぎる。ソケット差し替え前から出ていた指摘なので、SO-DIMM周辺の配置をやり直すこと |

`annular_width`(アニュラー幅ゼロ)と `padstack` は各10件あったが **2026-08に解消済み**。
原因はEasyEDA由来フットプリントの**機械取付穴が「穴径=パッド径のPTH」**になっていたこと
(アニュラーリングが負になり製造不可の指摘)。J2/J11(MagJack)・J6(3.5mmジャック)・
J9(USB-C)・U11(SO-DIMMソケット)の各2穴を **NPTH(`np_thru_hole`)に変更**した。
これらは樹脂ボスの位置決め穴なので非メッキが正しい。`parts/*/*.kicad_mod` と
`default.kicad_pcb` の両方を直してある(再取り込みすると戻るので注意)。
